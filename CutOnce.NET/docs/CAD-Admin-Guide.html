Before you start: the configuration file

Tasks 1 and 2, and option A of task 3, are done in CutOnce-Config.lsp, a plain text file. It is in the Contents folder of the install:

Installed forConfiguration file
One user (default)%APPDATA%\Autodesk\ApplicationPlugins\CutOnce.bundle\Contents\CutOnce-Config.lsp
All users (-Scope AllUsers)%ProgramData%\Autodesk\ApplicationPlugins\CutOnce.bundle\Contents\CutOnce-Config.lsp
Custom folder (-InstallDir)<that folder>\CutOnce-Config.lsp

Type CUTONCE-STATUS in Civil 3D to see the install folder in use.

  • Edit it with Notepad. Keep every quote mark and bracket; each setting looks like ("Key" . value).
  • Changes take effect when you type CUTONCE-RELOADCONFIG in Civil 3D, or when Civil 3D restarts. The .NET edition reads the file as data; it is never run as LISP, so a config from the LISP edition works unchanged.
  • To roll out one setup firm-wide, edit CutOnce.bundle\Contents\CutOnce-Config.lsp in the install package before handing it out. Reinstalling never overwrites a configuration file that is already there.

1. Add commands to watch

CutOnce shows its change-impact warning when certain Civil 3D commands start. You can add more commands to the Other watched commands (added by CAD admin) row of the Control Center.

  1. In Civil 3D, type CUTONCE-GUARD-LOGCOMMANDS. Every command name now prints on the command line as it starts.
  2. Start the command you want to watch the way designers do: from the ribbon, a menu or the command line.
  3. Write down the name that printed, for example AECCSOMECOMMAND.
  4. Type CUTONCE-GUARD-LOGCOMMANDS again to turn the echo off.
  5. Open CutOnce-Config.lsp and find this line: 
    ("ImpactExtraCommands" . nil)
    Replace nil with your names in quotes, separated by spaces: 
    ("ImpactExtraCommands" . ("AECCSOMECOMMAND" "AECCOTHERCOMMAND"))
  6. Save the file and type CUTONCE-RELOADCONFIG (or restart Civil 3D).
  7. Type CUTONCE and make sure Other watched commands is ticked. To stop designers turning it off, add it to the locked settings: 
    ("LockedSettings" . ("WarnOTHER"))
What the warning shows. It lists what depends on the alignment, profile or surface the designer selected before starting the command. With nothing selected, a command whose name contains SURFACE, PROFILE or ALIGNMENT reports on every object of that type. Any other command with nothing selected shows no warning, because there is nothing to analyse. The Control Center button How to add other watched commands... shows these steps too.

2. Report more data points in Health.csv

Health.csv records a row of counts every time a drawing is saved or opened. You can add a column for any other object type. CutOnce also includes your columns in the save-time growth warning.

  1. Open a drawing that contains the kind of object you want to count.
  2. Type CUTONCE-GUARD-DUMPOBJECTS. It lists every object type in the drawing by its exact name, with a count, for example AeccDbFeatureLine = 42.
  3. Open CutOnce-Config.lsp and find this line: 
    ("HealthExtraCounts" . nil)
    Replace nil with one ("ColumnName" . "ObjectName") pair per column: 
    ("HealthExtraCounts" . (("FeatureLines" . "AeccDbFeatureLine")
                        ("Polylines"    . "AcDbPolyline,AcDb2dPolyline,AcDb3dPolyline")
                        ("Dimensions"   . "AcDb*Dimension")))
  4. Save the file and type CUTONCE-RELOADCONFIG (or restart Civil 3D).
  5. Save any drawing, then open Health.csv (type CUTONCE-STATUS for the log folder). The new columns appear before the settings columns.
PartRules
ColumnNameLetters, digits and _ only (anything else is dropped). Must not repeat a built-in column such as Layers.
ObjectNameThe name from CUTONCE-GUARD-DUMPOBJECTS. Not case-sensitive. * matches anything, and commas combine several types into one count.
What is countedObjects in Model Space and every layout. Objects inside block definitions are not counted.
Growth warningYour columns use the same rule as the built-in ones: up by GuardGrowthWarnPct (default 20%) or more, or new since the last check.
Changing the list changes the columns. The first save afterwards renames the old file to Health-archived-<date>.csv and starts a new Health.csv, so no rows are lost and no file mixes two layouts. Close Health.csv in Excel first, or the rename waits until the next save.

3. Send logs to a shared team folder

By default each person's logs stay on their own PC in %LOCALAPPDATA%\CutOnce\Logs. For team reporting, point everyone at one shared folder and give each person their own subfolder inside it.

Pick the folder

Your setupUse
One office, file serverA network share, e.g. \\server\cad\CutOnce\Logs. Use the \\server path, not a mapped drive letter, so it works for everyone.
Several offices on a WAN or VPNOne network share every office can reach.
Offices without a shared serverA cloud-synced folder that every PC syncs locally (for example a SharePoint document library synced to each PC). Each PC writes to its local copy, and the sync service moves the files.

Everyone needs permission to create folders and files there (Modify). Nobody needs to delete anything.

Turn on per-person subfolders

With a shared folder, always use subfolders. Each person then writes only to their own files: two people never append to the same file at once, and synced folders never create "conflict" copies.

SettingLogs go toWhen
user-computerLogs\jsmith-CAD-PC12\Recommended. Safe even when one person uses two PCs.
userLogs\jsmith\Each person uses one PC.
computerLogs\CAD-PC12\Shared workstations.
noneLogs\Only for a local or single-user folder.

Option A: whole firm, before rollout (recommended)

  1. In the install package, open CutOnce.bundle\Contents\CutOnce-Config.lsp.
  2. Set the two log lines (use forward slashes): 
    ("LogDir"       . "//server/cad/CutOnce/Logs")
("LogSubfolder" . "user-computer")
  3. Save, then hand out the package. Everyone who installs it logs to the shared folder.

Option B: at install time

  1. Run the installer with the folder and subfolder options: 
    Install.cmd -LogDir "\\server\cad\CutOnce\Logs" -LogSubfolder user-computer
  2. Add -Scope AllUsers (from an administrator prompt) to set it for every user of the PC.

Option C: an existing install, step by step

  1. Close Civil 3D.
  2. Double-click Set-LogFolder.cmd in the install package.
  3. Pick the shared folder in the folder window. The script checks that you can write to it.
  4. Choose 1 for one subfolder per person per computer.
  5. Start Civil 3D and type CUTONCE-STATUS. The log folder line shows your subfolder.

To undo it, run Set-LogFolder.cmd -Clear. If the configuration file and Option B or C both set a folder, B or C (an environment variable) wins.

Combine everyone's logs in Excel

  1. In Excel: Data > Get Data > From File > From Folder, and pick the shared log folder.
  2. Choose Transform Data. Filter the Name column to Health.csv (or Events.csv, and so on).
  3. Click the Combine Files button on the Content column, then Close & Load.
  4. Next time, click Data > Refresh All to pick up new rows and new people.

Good to know

  • Growth warning history. The growth check compares a save with the last check of the same drawing in that person's own Health.csv, not other people's.
  • Built-in rollups. CUTONCE-GUARD-SUMMARY and CUTONCE-AUDIT read the current person's subfolder. Use Excel (above) for the team view.
  • Offline. If the shared folder cannot be reached, that log row is skipped; the warnings still work. A synced folder avoids this, because writes go to the local copy.
  • Uninstall. Uninstall.cmd -RemoveLogs never deletes a network, mapped-drive or per-person log folder.
  • Privacy. Logs contain Windows user names and drawing paths. Limit access to the shared folder to the people who need it.

4. Set up the shared backup folder

On save, the only CutOnce warning is unusual growth, and it offers Clean up now.... Before cleanup changes anything, CutOnce can copy the drawing (as last saved) into one shared "master" backup folder, so any earlier version can be recovered. The growth warning and the warnings for risky edits also have a Save a copy button that copies the drawing there before the designer goes ahead, and CUTONCE-BACKUP makes a copy at any time.

  1. Create the folder on a share everyone can reach, e.g. \\server\cad\CutOnce\Backups. Everyone needs permission to create files there (Modify). Nobody needs to delete anything.
  2. Point CutOnce at it, the same three ways as the log folder: 
    ("BackupDir" . "//server/cad/CutOnce/Backups")
    in CutOnce-Config.lsp, or Install.cmd -BackupDir "\\server\cad\CutOnce\Backups", or the CUTONCE_BACKUPDIR environment variable.
  3. To require a backup before every cleanup, lock it on: 
    ("BackupBeforeCleanup" . T)
("LockedSettings" . ("BackupBeforeCleanup"))
    If the copy then fails (share offline), cleanup stops without changing anything.
  4. Start Civil 3D and type CUTONCE-STATUS. The backup folder line shows the folder in use.
PartHow it works
File names<drawing>__<YYYYMMDD-HHMMSS-mmm>_<user>-<computer>.dwg, e.g. C-Grading__20261015-143005-789_jsmith-CAD-PC12.dwg. Time to the millisecond plus user and computer, and a -2, -3... counter if that name still exists, so a copy never overwrites another one.
What is copiedThe drawing file as last saved, so a copy made from a warning never includes the change being warned about. Cleanup offered on save runs right after that save, so its copy is the drawing before cleanup. With unsaved changes, CUTONCE-BACKUP asks whether to save first.
RecordEvery copy adds a row to Backups.csv in the person's log folder (original path, copy path, reason) and a BACKUP-COPY row to Events.csv. Backups.csv is written even with logging switched off.
DefaultWithout a setting, copies go to Documents\CutOnce Backups on each PC, and the cleanup dialog says so.
HousekeepingCutOnce never deletes copies, and uninstalling never touches them. Set a retention rule on the share if it should be pruned.

5. Set each project's coordinate system and units

The coordinate system and units check flags a drawing with no coordinate system, one that differs from its project or from an xref, Unitless insertion units, and insertion units that differ from the project or an xref. It runs when a drawing opens (standards check) and with CUTONCE-CHECK.

Tell CutOnce what each project uses. Easiest: put a text file named CutOnce-Project.ini in the project's top folder. CutOnce looks in the drawing's folder and each folder above it, and the nearest file wins.

; CutOnce project standard
CoordinateSystem=CA83-VIF
InsUnits=US Survey Feet

Or list projects by folder in CutOnce-Config.lsp (a CutOnce-Project.ini, when found, wins):

("ProjectStandards"
  . (("//server/projects/1234*" . (("CoordinateSystem" . "CA83-VIF")
                                   ("InsUnits" . "US Survey Feet")))))
PartRules
CoordinateSystemThe code shown in Drawing Settings > Units and Zone (or CGEOCS), e.g. CA83-VIF. Not case-sensitive.
InsUnitsA name (Feet, US Survey Feet, Meters...) or the INSUNITS number. Feet and US Survey Feet count as different.
No coordinate systemFlagged for every drawing. If many of yours (details, sheets) have none on purpose, set ("CoordSysRequired" . nil); project and xref mismatches are still flagged.
XrefsUnits come from each xref's insertion units. The coordinate system is read from a loaded xref's geographic location; an xref whose system cannot be read is not flagged.
LogsHealth.csv gets CoordinateSystem, ProjectCoordinateSystem and CoordUnitIssues; Xrefs.csv gets XrefInsUnits and XrefCoordinateSystem.

6. Brand the dialogs

Every CutOnce dialog shares one frame: a header in your brand colour with a logo tile, the name and tagline; a severity badge and colour strip (amber warning, red stop and check, green all clear, brand colour for information) next to the headline; and a footer with the version. Set your firm's look in CutOnce-Config.lsp:

("BrandName"    . "Acme Civil")
("BrandTagline" . "Built right the first time")
("BrandColor"   . "#0B6BCB")      ; a web colour, or an AutoCAD colour number (1-255)
("BrandLogo"    . "//server/cad/CutOnce/FirmLogo.png")
  1. Export your logo as a PNG, ideally square, at least 128 × 128 pixels, with a transparent background. It sits on a white tile, so a full-colour logo reads well.
  2. Save it to a shared folder and point BrandLogo at it, or name it CutOnce-Logo.png and put it in the install folder (next to CutOnce-Config.lsp).
  3. Pick the header colour: your brand's main colour as "#RRGGBB". Darker, saturated colours read best behind white text.
  4. Type CUTONCE-RELOADCONFIG, then CUTONCE-PREVIEW to see a sample warning, and CUTONCE for the Control Center.

Without a logo, CutOnce draws its own mark (a check above a dashed cut line) in the brand colour. BrandLogoSlide (.sld) from the LISP edition is not used any more; export the logo as a PNG instead. A BrandColor number from the LISP edition still works.

7. Stopping commands from their warnings

The LISP edition could only warn: designers clicked OK and pressed ESC. The .NET edition stops the command itself.

WarningButtons
Shown as a command starts: impact warnings with objects selected first, grip and surface edits, other watched commands, EXPLODE with objects selected first, REFEDIT, REFCLOSE, promote, TEXT / DTEXT / MTEXTStop <command>: cancels it before anything changes. Continue: lets it run.
MOVE, STRETCH, ROTATE or SCALE started with nothing selectedShown as a Civil 3D object with dependents is picked. Stop, Leave them out (removes those objects from the selection and carries on), Continue.
Shown after a command ran: EXPLODE / BURST, xref bind, xref moved or copiedUndo <command> (the same as typing U), Keep it.
  1. Designers switch this per person in the Control Center: Stopping a command has WarnOfferStop (Stop / Undo buttons) and WarnWhileSelecting.
  2. To make Stop available to everyone, set both to T and lock them: 
    ("WarnOfferStop"      . T)
("WarnWhileSelecting" . T)
("LockedSettings"     . ("WarnOfferStop" "WarnWhileSelecting"))
  3. Every stop and undo is logged to Events.csv as COMMAND-STOPPED, COMMAND-UNDONE or SELECTION-FILTERED, so you can see which warnings change what designers do.

How it works. Civil 3D announces each command as it takes the drawing, before it changes anything, and lets CutOnce veto it there. If a command ever misbehaves with a warning on screen at that moment, set ("StopOnLock" . nil): warnings then show as the command starts (as in the LISP edition) and Stop cancels it at its first prompt, the same as pressing ESC.

Troubleshooting

ProblemCheck
A change to the configuration file did nothingType CUTONCE-RELOADCONFIG and read what it prints (a broken bracket is reported with its line number in CUTONCE-STATUS). Make sure you edited the file in the folder CUTONCE-STATUS shows, and that every quote and bracket is still in place.
A watched command never warnsRun CUTONCE-GUARD-LOGCOMMANDS and compare the printed name with your list. Commands started from Toolspace's right-click menu may print nothing, which means CutOnce cannot see them.
An extra column is always 0Run CUTONCE-GUARD-DUMPOBJECTS in a drawing that has the object and copy the name exactly.
Rows are missingA log that is open in Excel cannot be written to; rows saved while it was open are skipped. Open the logs read-only, or use the Excel combine steps above, which do not lock them.
"Could not archive Health.csv"The file is open in Excel. Close it; the next save starts the new file.
CUTONCE-STATUS shows 2.1 or "Unknown command"The .NET edition did not load. Close Civil 3D and re-run Install.cmd from the 2.2 package (it replaces the LISP edition's files). If CutOnce was loaded from acaddoc.lsp, remove that (load ...) line. For a custom -InstallDir, add the folder and its Win64 subfolders to Trusted Locations.
"Unknown command" in one Civil 3D release onlyThe package was built without that release's DLL. Install.cmd warns about this; build the package on a PC with that release installed (see the developer guide).
The dialogs look plain or have no logoCheck BrandLogo points to a PNG or JPG that exists, then CUTONCE-RELOADCONFIG and CUTONCE-PREVIEW.
Stop does not appear on warningsThe designer switched off Offer Stop / Undo in the Control Center, or command warnings are off. CUTONCE-STATUS shows the Stop / Undo state.
Cleanup did not start after "Clean up now..."Type CUTONCE-CLEANUP. Cleanup is not offered while a drawing is being closed.
"Backup folder not reachable"Check the folder CUTONCE-STATUS shows exists and that the person can create files in it.
Every drawing says "No coordinate system"Assign one in Drawing Settings, or set ("CoordSysRequired" . nil). See step 5.
Logs still go to the old folderAn environment variable from the installer or Set-LogFolder.cmd wins over the configuration file. Run Set-LogFolder.cmd -Clear, then restart Civil 3D.
